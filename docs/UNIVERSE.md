# 時点整合ユニバースのデータ辞書

`src/stock_prediction/universe.py` は、日次の時点銘柄マスターを主表として、各シグナル日時点の
内国普通株式、上場後経過取引日数、流動性、価格形成を判定する。翌取引日始値と同週評価日終値を
使う売買可能性は事後proxyとして別列にし、シグナル時点の `is_eligible` には含めない。

## 入力

### 時点銘柄マスター

`auxiliary_data_download.py` の `listed_info/YYYY.parquet` を使用する。少なくとも次の列を必要とする。

| 列 | 型・意味 |
|---|---|
| `Date` | タイムゾーンなしの日付。この取引日時点のスナップショット |
| `Code` | 5文字の銘柄コード。数値変換しない |
| `ProdCat` | 3桁の商品区分。`"011"` を内国普通株式として採用 |
| `CoName` | 任意。会社名 |
| `Mkt`, `MktNm` | 任意。市場コード・名称 |

各東証取引日のスナップショットが必要で、欠落取引日を前後のマスターで補わない。
現行のJ-Quants銘柄マスターは東証の株式、ETF等、REIT等を含むため、マスターに存在するだけでは
普通株式とは判定しない。`ProdCat` が欠損または3桁文字列でなければ早期に停止する。

### 監査済み日次株価

`preprocessing.py` の年別出力から次の列を使う。

| 列 | 用途 |
|---|---|
| `date`, `code` | 時点マスターとの結合キー |
| `open`, `close` | 未調整の実売買価格proxy。エントリー始値、決済終値 |
| `volume`, `turnover_value` | 価格形成、流動性、売買可能性proxy。売買代金は円 |
| `upper_limit`, `lower_limit` | 文字列 `"0"` / `"1"`。買い・売りの保守的な値幅制限proxy |
| `has_price` | 前処理の品質検査に合格したOHLCV観測 |
| `calendar_verified` | 全行が真でなければ停止 |

株価行がない銘柄・取引日も、銘柄マスターの行は残る。価格や売買代金を0または前日値で補完しない。

### 取引カレンダーと任意スケジュール

取引カレンダーは全暦日の `Date` / `HolDiv` を持ち、`HolDiv` が `"1"` または `"2"` の日だけを
東証取引日とする。任意のスケジュールは次の3列だけを持つ。

| 列 | 条件 |
|---|---|
| `signal_date` | 暦週の最初の東証取引日 |
| `entry_date` | シグナル日の直後の東証取引日 |
| `exit_date` | シグナル日と同じ暦週の最後の東証取引日 |

スケジュール指定時は公式カレンダーに対して上記を検査する。祝日週も月曜・金曜という曜日ではなく、
実際の最初・最後の東証取引日で判定する。スケジュールを省略した場合は全マスター日を出力し、
事後売買可能性列をNullにする。

## 設定と判定

既定値は `configs/universe.json` に保存する。

| 設定 | 既定値 | 意味 |
|---|---:|---|
| `domestic_common_product_category` | `"011"` | 内国普通株式の商品区分 |
| `min_listing_sessions_elapsed` | 60 | 初回観測取引日を0として必要な経過取引日数 |
| `liquidity_window_sessions` | 20 | シグナル日を含む過去窓 |
| `min_price_formation_days` | 15 | 20日窓で必要な価格形成日数 |
| `min_median_turnover_yen` | 100,000,000 | 有効な価格形成日の売買代金中央値下限 |
| `planned_investment_yen` | 1,000,000 | 1銘柄当たり予定投資額 |
| `max_participation_rate` | 0.01 | 売買代金中央値に対する参加率上限 |

価格形成日は `has_price=True`、`volume > 0`、`turnover_value > 0`、`close > 0` をすべて満たす日とする。
中央値は価格形成日の売買代金だけから計算するが、別途15/20日条件を課す。短い20日窓では計算済みの
中央値があっても `has_full_liquidity_window=False` とし、流動性合格にはしない。

```text
max_order_value_yen_20 = median_turnover_value_20 * max_participation_rate

is_liquid =
  20取引日の完全な履歴
  and 価格形成15日以上
  and 売買代金中央値1億円以上
  and 予定投資額100万円 <= max_order_value_yen_20
```

上場日を直接示す列はないため、連続する銘柄マスタースナップショット内での経過日数を使う。
入力開始日にすでに存在する銘柄も、入力内で60取引日の経過を確認するまで除外する。消失後に同じコードが
再出現した場合は0へ戻す。年別処理は直前60取引日だけを引き継ぐため、出力の
`listed_sessions_elapsed` は60で上限を切る。これは「少なくとも60日」を意味し、真の上場日を推定しない。

## 主な出力

| 列 | 意味 |
|---|---|
| `signal_date`, `code` | 主キー |
| `is_domestic_common_stock` | 当日の `ProdCat` が `"011"` |
| `listed_sessions_elapsed` | 連続上場を入力内で確認した経過取引日数。60で上限 |
| `has_min_listing_history` | 60取引日以上を確認 |
| `liquidity_window_observations` | 現在の連続上場区間で20日窓に入ったマスター観測数 |
| `price_formation_days_20` | 直近20取引日の価格形成日数 |
| `median_turnover_value_20` | 価格形成日における未調整売買代金の中央値、円 |
| `max_order_value_yen_20` | 参加率上限から算出した1銘柄の注文上限、円 |
| `is_liquid` | 20日履歴、15日価格形成、1億円、参加率をすべて満たす |
| `signal_price_available` | 正の有限なシグナル日終値がある |
| `signal_price_formed` | シグナル日に正の出来高・売買代金を伴う価格形成がある |
| `is_eligible` | 内国普通株式、60日、流動性、シグナル日価格形成をすべて満たす |
| `exclusion_reasons` | `is_eligible=False` の理由をセミコロン区切りで列挙 |

任意スケジュールを指定した場合は次の事後列も生成する。

| 列 | 意味 |
|---|---|
| `entry_price`, `exit_price` | 翌取引日の未調整始値、同週評価日の未調整終値 |
| `entry_not_limit_up` | エントリー日のストップ高フラグが `"0"` |
| `exit_not_limit_down` | 決済日のストップ安フラグが `"0"` |
| `is_entry_executable` | 始値、正の出来高・売買代金、ストップ高なしを確認 |
| `is_exit_executable` | 終値、正の出来高・売買代金、ストップ安なしを確認 |
| `is_executable` | エントリーと決済の両proxyを満たす |

`is_executable` は事後評価・未約定処理用であり、シグナル時点の銘柄選定や特徴量に使わない。
日足だけでは始値で実際に希望株数が約定したこと、板の厚さ、日中の値幅制限到達順を確定できない。

## 既知の制限

- 現行入力には監理・整理指定の履歴がないため、その除外を検証済みとはしない。
- `upper_limit` / `lower_limit` と日次出来高による判定は保守的なproxyで、約定保証ではない。
- 銘柄コード変更候補を確定イベントとして連結しない。同じコードの消失・再出現は履歴をリセットする。
- 決算跨ぎと決算後25取引日のクールダウンは本工程の対象外で、後続の決算イベント工程で判定する。
- 閾値は2025年以降の最終バックテストを見て変更しない。感度分析も開発期間で設計する。
