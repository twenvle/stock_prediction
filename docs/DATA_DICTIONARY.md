# 日次株価データ辞書

本書は `src/stock_prediction/preprocessing.py` が読み込む J-Quants API v2 の日次株価と、監査済み中間データの意味を定義する。入力は取得済みの `data/raw/` の Parquet であり、原本を変更しない。出力は `data/interim/` に保存する。投資可能ユニバース、特徴量、週次目的変数、決算除外、売買判定はこの段階では生成しない。後続の特徴量工程は [日次テクニカル特徴量のデータ辞書](DESCRIPTORS.md)、ユニバース工程は [時点整合ユニバースのデータ辞書](UNIVERSE.md) を参照する。

## API取得スナップショット

`src/stock_prediction/data_download.py` はJ-Quants API V2のレスポンス値を補完・補正せず、
実行ごとの `data/raw/jquants_v2_<UTC実行ID>/` にParquetで保存する。Parquetで型を一意に
保つため、`Date` はタイムゾーンなしの日付型、コード・フラグ・`ExRT` は文字列型、
数値・Null列は浮動小数点型へ正規化し、列順をV2仕様順へ固定する。値の補完や丸めは行わない。

- `trading_calendar.parquet`：要求範囲の全暦日。列は `Date` と `HolDiv` の2列だけ。
- `prices/YYYY.parquet`：完了した暦年（または要求範囲内の年部分）の日次株価。
- `partial_prices/YYYY.parquet`：中断・失敗した年に取得済み行がある場合だけ。
- `manifest.json`：要求範囲、取得日時、API版、行数、銘柄数、実日付範囲、列別欠損率、
  重複数、完了日数、ファイルSHA256、実行ライブラリ版、完了/中断/失敗状態。

APIキーはデータでも来歴情報でもないため保存しない。manifestの
`credential_persisted=false` はキーを保存していないことを示し、認証成功そのものの証明ではない。
既存スナップショットへ追記・上書きせず、再取得時は別の実行IDを作る。これにより後日の
訂正や調整済み価格の遡及変更があっても、各取得時点のファイルを区別できる。

### 補助データ取得スナップショット

`src/stock_prediction/auxiliary_data_download.py` は次を
`data/raw/jquants_v2_auxiliary_<UTC実行ID>/` へ保存する。日付列はタイムゾーンなしの
日付列は日時型、コード・分類・時刻は文字列として固定する。TOPIX等のAPI数値型は浮動小数点で
保存するが、`/fins/summary` の財務値は公式レスポンスどおり文字列（未記載は空文字列）のまま
保持する。未知列は保存前にエラーとし、原本値の補完、未来の値による上書き、現在銘柄からの
過去再構成は行わない。

| ファイル | 主な列・時点 | 主キーまたは重複検査 |
|---|---|---|
| `topix.parquet` | `Date`, `O`, `H`, `L`, `C`。値は指数ポイント。`C` は同日引け前には未知 | `Date` |
| `listed_info/YYYY.parquet` | `Date` 時点の `Code`, 会社名, 17/33業種, 規模, 市場, 信用区分, 商品区分 | `(Date, Code)` |
| `earnings_schedule/YYYY.parquet` | `PubDate`（予定情報の公表/利用可能日）, `SchDate`（予定発表日）, 四半期・決算期, `Code` | 完全重複を拒否。監査キーは `(PubDate, Code, FQName, SchDate)` |
| `financial_results/YYYY.parquet` | `DiscDate`, `DiscTime`（日本時間の開示時点）, `DiscNo`, `DocType`, 対象期間, 財務値。日付列以外は公式仕様どおり文字列で、未記載値の空文字列を保持 | `(DiscDate, DiscNo)` |
| `master_transitions/YYYY.parquet` | 連続する取得営業日間の `appeared`, `disappeared`, `attributes_changed` | `(ObservedDate, Code, ChangeType)` |
| `code_change_candidates/YYYY.parquet` | 同じ境界で会社名が一意に完全一致した旧・新コード候補 | `(ObservedDate, OldCode, NewCode)` |

決算予定の `PubDate` と `SchDate`、財務実績の対象期間と `DiscDate` / `DiscTime` を混同しない。
モデルで利用可能かは原則として公表・開示時点で判定する。財務数値を決算期末日に結合しない。
決算予定・実績は休日の公表を取りこぼさないよう全暦日、銘柄マスターは公式カレンダーの
東証営業日だけを問い合わせる。空の決算日を正常な0件として保持できる安定schemaを使用する。

`master_transitions` の出現・消失は2つの観測間の差であり、法的な新規上場・上場廃止、
売買停止、合併の理由を示さない。最初の取得営業日はbaselineなので、その日の変化も判定できない。
`code_change_candidates` は会社名一致だけの非確定候補で、manifestにも
`code_change_candidates_are_authoritative=false` を保存する。確定イベントとして使うには、
旧新コードを結ぶ公式コーポレートアクション情報との照合が必要である。

取得時は下記16列を必須とする。公式の日次株価レスポンスに含まれる `MktCap` と `ExRT` は
既知の任意列として原本へ保持する。`MktCap` は数値またはNull、`ExRT` は文字列
`"1"` / `"2"` / `"3"` またはNullに限定する。`MktCap` は公式に本APIから削除予定と
案内されているため、列がないレスポンスも受理する。契約プランにより提供される既知の前場列
`MO/MH/ML/MC/MUL/MLL/MVo/MVa/MAdjO/MAdjH/MAdjL/MAdjC/MAdjVo` と後場列
`AO/AH/AL/AC/AUL/ALL/AVo/AVa/AAdjO/AAdjH/AAdjL/AAdjC/AAdjVo` は、そのまま追加保持する。
それ以外の未知列、必須列欠落、`(Date, Code)` 重複、要求日以外の価格行、非文字列コード・
フラグはAPI仕様変更または不正レスポンスとして保存前にエラーにする。数値列は数値または
Nullを許容する。取引がない日のOHLC・出来高・売買代金はNullになり得るため、取得時には
補完・除外しない。物理的なOHLC整合性等は後続の前処理で検査する。

## 入力スキーマ

実データで確認した必須列は次の **16列**。`Date` は Arrow `timestamp[ns]`、`Code`・`UL`・`LL` は Arrow `string`、それ以外は Arrow `double`。既知の任意列が付く場合は型・値を検査して入力原本に保持するが、基礎前処理は次の16列だけを読み込む。列名、型、日付形式、銘柄コード形式を検査し、未知の追加列や不足列はエラーとする。数値は有限値であること、価格は正、数量・売買代金は非負、調整係数は正であることを検査する。

| 原列 | 中間データ列 | 単位・意味 |
|---|---|---|
| `Date` | `date` | 観測取引日。日付のみ、タイムゾーンなしの日時。公表日時・取得日時ではない |
| `Code` | `code` | 銘柄コード文字列。先頭ゼロ・英字を保持し、数値へ変換しない |
| `O` | `open` | 未調整始値、円 |
| `H` | `high` | 未調整高値、円 |
| `L` | `low` | 未調整安値、円 |
| `C` | `close` | 未調整終値、円 |
| `UL` | `upper_limit` | ストップ高フラグ。原値は文字列 `"0"` / `"1"` |
| `LL` | `lower_limit` | ストップ安フラグ。原値は文字列 `"0"` / `"1"` |
| `Vo` | `volume` | 未調整出来高。普通株式は株数、ETF・REIT等は口数 |
| `Va` | `turnover_value` | 売買代金、円。調整済み出来高と未調整株価を掛けて代替しない |
| `AdjFactor` | `adjustment_factor` | 株式分割・併合等の調整係数。通常は1、正の有限値 |
| `AdjO` | `adjusted_open` | 提供された調整済み始値、円 |
| `AdjH` | `adjusted_high` | 提供された調整済み高値、円 |
| `AdjL` | `adjusted_low` | 提供された調整済み安値、円 |
| `AdjC` | `adjusted_close` | 提供された調整済み終値、円 |
| `AdjVo` | `adjusted_volume` | 提供された調整済み出来高。数量単位は `Vo` と同じ |

基礎前処理へ複製しない既知の任意列は次のとおり。これらを特徴量として使用する場合は、
利用可能時点と定義を確認した別工程で明示的に採用する。

| 原列 | 原本での型 | 単位・意味 |
|---|---|---|
| `MktCap` | Arrow `double` | 時価総額、百万円。調整前終値と上場株式数から算出。公式に日次株価APIから削除予定 |
| `ExRT` | Arrow `string` / `large_string` | 権利落種類。`"1"`=株式分割、`"2"`=株式併合、`"3"`=ライツイシュー、該当なしはNull |

`UL` は高値がストップ高に達した場合のフラグであり、終値で買えることや買い注文が約定することを保証しない。`LL` も約定可否そのものではない。両フラグの判定と価格・数量の仕様は [J-Quants API v2 日次株価仕様](https://jpx-jquants.com/ja/spec/eq-bars-daily) に従う。

## 主キーと品質検査

- 主キーは `(date, code)`。重複を黙って1行へまとめず、検出件数と扱いを監査結果へ残す。
- 未調整・調整済みの双方で `low <= open <= high` と `low <= close <= high` を検査する。
- 不正な価格、数量、係数、非有限値、部分的な価格欠損、主キー不正、カレンダーとの不整合は補正せず隔離する。
- 日付範囲、行数、銘柄数、列別・日付別・銘柄別の欠損率、重複・隔離件数を監査可能にする。
- 株価、数量、売買代金を前方補完しない。銘柄コード変更・上場廃止・合併を株価ファイルだけから推定しない。

OHLC・出来高・売買代金がすべて欠損する行は、価格形成がなかった観測として保持する。無約定と売買停止のどちらかは株価データだけでは判別できないため、理由を確定しない。価格や数量の一部だけが欠損する行は整合性不明として隔離する。

## 追加列

これらは品質検査と研究期間の識別用であり、学習に使う特徴量ではない。

| 列名 | 意味・注意 |
|---|---|
| `has_price` | 未調整・調整済みOHLC、数量・売買代金がそろい、行の品質検査に合格したこと。売買可能性の保証ではない |
| `is_adjustment_event` | `adjustment_factor != 1` の観測。株式分割・併合等の確認対象として保持する |
| `calendar_verified` | 明示的な東証取引カレンダーで取引日を確認したか。カレンダー未提供なら偽 |
| `research_period` | `development`（2016〜2024年）、`final_backtest`（2025〜2026年）等の期間区分。最終期間の値を前処理閾値の推定に使わない |
| `previous_observation_date` | 同一銘柄の直前の観測行の日付。欠損観測を飛ばして前の価格を探索しない |
| `observed_adjusted_close_return` | 同一銘柄の直前の観測行の `adjusted_close` に対する単純価格リターン `current / previous - 1`。現在・直前の価格が欠損なら欠損。観測間隔を1取引日と仮定しない |
| `is_large_return` | 上記リターンの絶対値が設定の監査閾値を超えたこと。自動除外・補正をしない |
| `is_non_finite_return` | 有限・正の価格同士の比を計算した際に数値オーバーフロー等が起きたこと。リターンは欠損にし、件数を報告する |

銘柄別・日付順に計算し、年別ファイル間でも前の観測を引き継ぐ。未来の観測行に基づく補完・統計推定は行わない。`observed_adjusted_close_return` は異常値監査用であり、週次ターゲット、総収益、約定リターン、東証営業日間の確定した日次リターンではない。

重複行や不正価格行は利用可能な価格と扱わず、その翌観測の比較元を古い有効価格へ遡らせない。
数値列のゼロ数量はREADMEの非負性制約を満たすため保持し、`zero_quantity_rows` で監査する。
`UL`/`LL` の欠損は未知のフラグとして保持し、列別欠損率に含める。

## 調整済み系列と時点整合性

調整済みOHLC・出来高は入力スナップショットの値を保持し、前処理で再調整しない。提供元の調整済み系列は後日のコーポレートアクション等によって過去へ遡って変わり得るため、取得済みファイルが各観測日の時点で取得できた情報だけを含むとは保証できない。この中間データをそのまま時点整合的な学習データとみなさない。

入力ファイルのハッシュと処理設定によって使用したスナップショットを識別する。実際のAPI取得日時や履歴スナップショットが原データにない場合は、それらを処理日時やファイル更新日時で代替しない。学習用データを生成する前に、歴史的な調整済み価格・銘柄マスター・開示日時等の利用可能時点を別途確認する。

J-Quantsの価格調整に現金配当は含まれない。調整済み終値比は価格リターンであり、配当込み総収益として扱わない。[J-Quants API v2 日次株価仕様](https://jpx-jquants.com/ja/spec/eq-bars-daily)

## 任意の取引カレンダー

カレンダーを渡す場合、v2の `Date` / `HolDiv` を用い、少なくとも処理する最小日から最大日までの **全暦日** を含むことを確認する。株価の観測日集合を営業日カレンダーの代わりにしない。

| `HolDiv` | 意味 | 東証株価の扱い |
|---|---|---|
| `"0"` | 休業日 | 閉場 |
| `"1"` | 営業日 | 開場 |
| `"2"` | 半日立会 | 開場 |
| `"3"` | OSE休日取引日 | 東証は閉場 |

未提供時はカレンダー確認済みと記録せず、祝日・営業日連続性・上場後経過営業日数・週次シグナル日を推定しない。営業日コードは [J-Quants API v2 営業日カレンダー仕様](https://jpx-jquants.com/ja/spec/mkt-cal/holiday-division) に従う。

## 依存関係

`requests` はHTTPS通信、`pandas` は表の整形・検査、`numpy` は数値の有限性検査、
`pyarrow` はParquetの型確認・期間選択・読み書きに使用する。取得処理はAPIページごとの
レート制御と429/5xx再試行を独自に管理するため、外部APIクライアントライブラリには依存しない。
依存範囲は `pyproject.toml` で一元管理し、`environment.yml` は同じプロジェクトの開発用
インストールを行う。検証した実バージョンと範囲は実装計画に記録し、許容ライブラリ版
すべてでの動作を保証するものではない。
