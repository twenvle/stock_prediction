# 売買バックテスト仕様

## 1. 責務と時点基準

`src/stock_prediction/backtest.py` は、保存済み予測を実際に売買可能な条件へ変換し、注文、約定、
保有、日次資産、ターンオーバーを分離して保存する。予測精度用のシグナル日終値から評価日終値までの
targetは、銘柄選択、約定可否、コスト、損益へ使用しない。

主設定は次のとおりである。

- シグナル日の終値確定後に予測順位を作る。
- 買いは次の東証取引日の未調整始値で一度だけ試行し、未約定残は当日失効する。
- 売りは評価日の未調整終値で試行する。設定を `next_session_open` にすると、評価日翌取引日の
  未調整始値へ変更できる。
- 売りが値幅制限、無取引、価格欠損、参加率で約定できない場合、後続取引日の同じ価格種別で
  最大 `max_exit_wait_sessions` 回まで繰り越す。期間末まで残る保有を削除せず、主結果を未完了とする。
- 片道コストの初期値は手数料5bps、半スプレッド5bps、スリッページ10bpsである。これは一般的な
  市場標準ではなく、ユーザー確認済みの変更可能な初期値である。

## 2. DataFrame入力

### 2.1 予測

少なくとも次の列を必要とする。

| 列 | 意味 |
|---|---|
| `signal_date` | 特徴量と予測が確定する取引日 |
| `code` | 5文字銘柄コード |
| `model` | モデル名 |
| `target_column` | モデルが学習したtarget名 |
| `prediction` | 有限値なら順位付け可能な予測値 |

`model_name` と `target_column` に一致する行だけを使い、同じ `(signal_date, code)` の重複を拒否する。
`actual_target` や `target_observed` が入力にあっても読み取らない。

### 2.2 週次候補表

既定では `weekly_dataset.py` の年別成果物を用い、次を必要とする。

| 列 | 意味 |
|---|---|
| `signal_date`, `code` | 予測との完全一致キー |
| `entry_date` | シグナル日の次の公式取引日 |
| `exit_date` | 同じ週の評価日 |
| `is_signal_eligible` | シグナル時点情報だけで作った適格性 |
| `median_turnover_value_20` | シグナル時点までの過去20取引日売買代金中央値 |
| `lot_size` | 任意の時点別売買単位。Nullまたは列なしなら設定値を使用 |

参加率上限は `median_turnover_value_20 * max_participation_rate` とする。当日の全日売買代金を
当日始値注文のサイズ決定へ使わない。既定売買単位は100株だが、過去または個別銘柄で異なる場合は
時点別 `lot_size` を候補表へ付与する。設定値を使った件数はmanifestへ記録する。

### 2.3 監査済み日次株価

`preprocessing.py` の年別成果物から、次の列だけを読む。

`date`, `code`, `open`, `close`, `upper_limit`, `lower_limit`, `volume`,
`turnover_value`, `adjustment_factor`, `has_price`, `calendar_verified`

現金損益と株数には未調整価格を使う。`adjustment_factor != 1` の日は、その日の始値より前に
保有株数を `shares / adjustment_factor` へ変更し、変更前後を `corporate_actions.parquet` に残す。
価格は前方補完しない。日次評価だけは、保有を消さないため直近の実価格を時価として保持し、
その件数を `stale_mark_positions` に記録する。

### 2.4 取引カレンダー

J-Quantsの `Date`, `HolDiv` を持つ完全な暦日カレンダーを使う。`HolDiv` が `"1"` または
`"2"` の日だけを東証取引日とし、`entry_date` がシグナル日の直後の取引日であることを検査する。

### 2.5 上場廃止清算表

任意入力であり、確定イベントだけを記録する。

| 列 | 意味 |
|---|---|
| `code` | 5文字銘柄コード。1実行内で1行まで |
| `delisting_date` | 上場廃止日 |
| `settlement_date` | 現金対価等を資産へ反映する日 |
| `settlement_value_per_share` | 旧株1株当たりの実際の経済的清算価値 |

MBO、株式交換、合併、破綻などの理由だけから清算価値を推測しない。値が既知ならその値で清算し、
売買手数料・スプレッド・スリッページは課さない。保有中の確定上場廃止に値がない場合、既定の
`unresolved_delisting_policy="error"` は `UnresolvedDelistingError` を発生させ、manifestを
`failed` とする。全損感度分析は別実行で `"write_off"` を明示し、理由列へ
`unresolved_delisting_write_off_sensitivity` を残す。価格欠損や銘柄マスターからの消失だけを
上場廃止と推測しない。

## 3. 選択、株数、参加率

各シグナル日について、適格かつ有限予測の銘柄を予測降順、同値はコード昇順で並べ、上位Nを選ぶ。
買い前の利用可能現金を選択数で等分し、次の3上限の最小値を売買単位へ切り下げる。

```text
予算上限株数 = floor(1銘柄予算 / コスト込み1株価格 / 売買単位) * 売買単位
資金上限株数 = floor(利用可能現金 / コスト込み1株価格 / 売買単位) * 売買単位
参加率上限株数 = floor(
    シグナル時点売買代金中央値 * 参加率 / 未調整約定基準価格 / 売買単位
) * 売買単位
```

参加率だけが小さい場合は部分約定とし、残注文は失効する。1単位にも満たない場合は未約定になる。
前週の売りが遅れて同一銘柄を保有中なら、新規買いを行わない。

## 4. 約定可否とコスト

買いは `has_price=True`、正の有限始値、正の出来高・売買代金、`upper_limit="0"` をすべて必要とする。
売りは対応する価格に加え `lower_limit="0"` を必要とする。値幅フラグが1の日は一日全体を
未約定とする保守的proxyであり、板・気配・約定時刻を再現したものではない。

基準価格を `P`、半スプレッド、スリッページ、手数料のbpsをそれぞれ `s`, `l`, `c` とする。

```text
買い実効価格 = P * (1 + (s + l) / 10000)
売り実効価格 = P * (1 - (s + l) / 10000)
手数料 = 実効約定代金 * c / 10000
```

注文・約定台帳には、基準価格、実効価格、手数料、スプレッド費用、スリッページ費用を別々に保存する。
コスト0は参考感度分析に限定し、主結果の設定をmanifestで確認する。

## 5. 出力

| ファイル | 内容 |
|---|---|
| `orders.parquet` | 全注文試行、未約定理由、要求・約定・残株数、参加率上限、コスト |
| `trades.parquet` | 実際に約定または清算した取引台帳 |
| `positions.parquet` | 建玉ごとの入口、予定・実際の出口、株数、損益、状態 |
| `corporate_actions.parquet` | 調整係数による保有株数変更 |
| `daily_portfolio.parquet` | 現金、時価、総資産、日次収益、累積収益、ドローダウン、古い時価件数 |
| `weekly_metrics.parquet` | シグナル別の選択・約定coverage、売買額、コスト、損益、ターンオーバー |
| `yearly_metrics.parquet` | 年別収益、ボラティリティ、Sharpe、最大DD、コスト、ターンオーバー |
| `summary_metrics.parquet` | 累積・年率収益、ボラティリティ、Sharpe、最大DD、Calmar、勝率、損益比、全体coverage |

ターンオーバーはシグナル日時点資産を分母に、`two_way_turnover` を売買代金合計、
`one_way_turnover` をその半分として明記する。上場廃止の現金清算は市場売買ではないため分子から除き、
`delisting_settlement_cash` に分ける。銘柄数不足、未約定、部分約定を補充で隠さない。

## 6. 既知の制限

- 日次OHLCVでは寄付き・引けの板、気配数量、注文優先順位、実際の部分約定を復元できない。
- 値幅制限フラグがある日は常に売買不能とするため、実際より保守的になり得る。
- 配当、税金、信用金利、貸株料は含まない。現状は価格リターンのロングオンリー現物戦略である。
- 時点別 `lot_size` がない行は既定100株を使う。異なる売買単位を含む期間では必ず入力を補う。
- 調整係数後に端株が生じ、通常売買単位で決済できない場合は保有が残り、主結果は未完了になる。
- 上場廃止情報は別の確定入力が必要であり、現在の `master_transitions` は使用できない。
- 実データ週次候補表、予測、確定上場廃止清算表がまだ揃っていないため、実投資成績は未検証である。
