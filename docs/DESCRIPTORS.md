# 日次テクニカル特徴量のデータ辞書

本書は `src/stock_prediction/descriptors.py` の入力契約、数式、欠損の意味、保存形式を定義する。
この工程は前処理済みの日次観測行から説明変数を作るだけであり、週次シグナル日、投資可能
ユニバース、決算除外、目的変数、欠損補完、外れ値処理、標準化は生成しない。

## 入力

`compute_descriptors` は、`preprocessing.py` が生成した次の列を使う。追加列は無視するが、
必須列の型・値、`(date, code)` の一意性、価格整合性を再検査する。

| 列 | 型・単位 | 用途 |
|---|---|---|
| `date` | timezoneなしの日付 | 日本の取引セッション日 |
| `code` | 5文字の文字列 | 銘柄境界。数値へ変換しない |
| `adjusted_close` | float、円 | モメンタム、SMA、対数リターン、レンジ位置 |
| `adjusted_high` / `adjusted_low` | float、円 | 20セッションの高値・安値レンジ |
| `adjusted_volume` | float、株または口 | 分割・併合を調整した出来高比 |
| `turnover_value` | float、円 | 未調整の売買代金比 |
| `has_price` | bool | 偽の行は価格形成なしとして全特徴量を欠損にする |
| `calendar_verified` | bool | 全行が真であることを必須とする |

これに加え、J-Quants V2の `Date` / `HolDiv` 取引カレンダーを必須とする。全暦日を含む
カレンダーのうち `HolDiv` が文字列 `"1"` または `"2"` の日だけを東証取引セッションとする。
観測行の個数や平日から営業日を推定しない。ある銘柄の日次行が欠けている場合、その欠落を
飛び越えて短い行窓を所定の取引セッション窓として扱わない。

TOPIXは任意で、正規化済みの `date` / `close` 2列を受け取る。`date` は一意な東証取引日、
`close` は正の有限値または欠損とする。価格を前方補完しない。TOPIXが未指定なら
`RelativeTOPIX_20` だけを全欠損とし、他の特徴量は通常どおり計算する。

## 出力列と数式

すべてシグナル日を含む当日終値後に確定する日次特徴量である。`P`、`High`、`Low` は
調整済み価格、`V` は調整済み出来高、`T` は未調整売買代金を表す。

| 列 | 定義 | 必要な履歴 |
|---|---|---|
| `R_5` | `P_t / P_(t-5) - 1` | 5セッション前の終値 |
| `R_20` | `P_t / P_(t-20) - 1` | 20セッション前の終値 |
| `R_60` | `P_t / P_(t-60) - 1` | 60セッション前の終値 |
| `PriceToSMA_20` | `P_t / mean(P[t-19:t]) - 1` | 20個の連続した終値 |
| `SMA_5To20` | `mean(P[t-4:t]) / mean(P[t-19:t]) - 1` | 20個の連続した終値 |
| `Volatility_5To20` | 5日対数リターン標準偏差 / 20日対数リターン標準偏差 | 20個の連続した日次対数リターン |
| `Volatility_20` | 20日対数リターンの標準偏差 | 20個の連続した日次対数リターン |
| `RangePosition_20` | `(P_t - min(Low[t-19:t])) / (max(High[t-19:t]) - min(Low[t-19:t]))` | 20個の連続したOHLC観測 |
| `VolumeRatio_5To20` | `mean(V[t-4:t]) / mean(V[t-19:t])` | 20個の連続した出来高観測 |
| `TurnoverRatio_5To20` | `mean(T[t-4:t]) / mean(T[t-19:t])` | 20個の連続した売買代金観測 |
| `RelativeTOPIX_20` | `R_20 - R_TOPIX_20` | 銘柄とTOPIXの20セッションリターン |

標準偏差は設定 `volatility_ddof` を使い、既定値は標本標準偏差の1である。rolling集計は
窓と同数の有限値を必須とする。履歴不足、窓内欠損、非連続セッション、分母0、非有限な演算、
レンジ幅0は欠損にする。欠損を短い窓、古い価格、0で代替しない。外れ値もこの工程では切らない。

出力は `date`、`code`、上記11列の順で、入力日次行と1対1である。これは銘柄選択済みの
学習表ではない。後続工程は週次シグナル日と時点整合的ユニバースで行を選び、学習fold内だけで
補完・外れ値境界・標準化をfitする。

## 保存APIと来歴

`run_descriptors` とCLIは年別Parquetを順番に読み、銘柄ごとの直前60セッションを次年へ渡す。
全年度を一括でメモリへ連結しない。出力先は新規ディレクトリに限り、既存ファイルを上書きしない。

```text
data/processed/descriptors_<UTC実行ID>/
  YYYY.parquet
reports/descriptors_<UTC実行ID>/
  YYYY.json
  manifest.json
```

年別レポートとmanifestには、入力/出力行数、銘柄数、実日付範囲、価格なし行数、特徴量別の
欠損率と利用可能件数、入力/出力SHA256、設定、TOPIX有無、コードSHA256、ライブラリ版、
開始・終了時刻、完了済みpartition、完了/失敗/中断状態を保存する。乱数は使わない。

調整済み価格は取得後のコーポレートアクションによって過去へ遡って改定され得る。manifestは
使用した中間データをハッシュで識別するが、各観測日に実際に入手可能だった絶対水準までは
証明しない。入力スナップショットの取得時点と調整方針は実験結果とともに確認する。
